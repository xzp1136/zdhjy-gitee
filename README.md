# 真的好解压 · Cocos 重制工程

这是使用 **Cocos Creator 3.8.7** 制作的本地重制工程。项目复用用户提供的 Unity 运行包美术、音频和静态配置，并对照桌面微信原版实现花店首页、花池订单玩法和结算流程。**目前尚未完成完整的 1:1 复刻**；已提取的原表、已实测的行为与本地适配策略分别记录在下文。

## 打开与预览

1. 在 Cocos Dashboard 添加 `/Users/zhangxiaoqiang/gitProject/ZDHJY`，使用 **3.8.7** 打开。
2. 等待资源导入完成，打开 `assets/FlowerGame.scene`，运行浏览器预览。
3. 使用编辑器返回的预览地址。布局基准为 **750 × 1334**；首页关卡按钮进入当前存档关卡。

`FlowerGame` 组件在运行时创建界面，编辑模式不会显示完整的运行 UI。工程配置了 Funplay Cocos MCP，辅助脚本默认连接 `http://127.0.0.1:8765/`，可用 `COCOS_MCP_URL` 覆盖。连接前须确认编辑器打开的是本工程。

本地进度、金币、星星、道具次数和设置保存在浏览器 `localStorage` 的 `zdhjy.*` 键中，不与微信账号同步。不同浏览器、预览域名或清理站点数据会影响存档。

运行入口通过 `FlowerCatalog` 读取原表，首关标记为 `observed`，后续目录内关卡标记为 `extracted`。`FlowerRules.makeFlowerLevel()` 仍保留确定性生成配置供独立规则测试使用，**主流程已经不使用它生成后续关卡**。`extracted` 表示结构来自原表，不表示运行时随机、布局和全部业务已一致。

当前适配选择 **B 分支**：四套表中仅 B 的第二关包含特殊气泡配置，与本次实测见到蝴蝶气泡相符。这是有依据的分支推断，尚未还原服务端选 A/B/C 的完整条件。花种随机选择使用固定本地种子，不保证与原版某次开局一致。

原始代码确认：订单组缺失或该组没有当前已解锁花束时，记录警告并跳过；不借用基础表，也不强行使用未解锁花束。适配器遵循此行为，包括 B/C 第 53～61 关缺组的原始数据差异；如果跳过后没有有效订单，则明确报错。原始 JSON 保持原样。

## 已确认的玩法与当前实现

- **首关**：180 秒，蓝绣球、紫木槿、粉金鱼草各 3 朵，共 9 朵；初始 2 个订单槽。每完成一单 +1 星，实际通关获得 **10 金币、3 星**。
- **第二关**：原表为 400 秒、31 张订单，包含两张六花复合订单，按订单需求实际累计 **99 朵花**。初始 4 槽；原代码条件是“关卡等于 2”，其它关初始默认 2 槽，不能把四槽外推到所有后续关卡。
- **订单**：按原需求支持单花种和多花种花束，混合花束按原组顺序收花；只匹配当前未完成组，下一组的花先暂存。普通暂存和清除后的待回填花会自动匹配，待回填区优先。暂存初始 5 格，第 6 格价格 60 金币。
- **进度**：HUD 已接入原 `GameMgr.ReduceFlowerNum` 的非线性百分比，并按 `f32` 运算顺序实现；首关 1/3/6 朵显示 25/56/77%，第二关 3/6/9/12/15/18 朵显示 7/14/21/27/32/37%。实际收集比例与显示百分比分开保存。
- **花池表现**：首关全部九朵露出；后续读取原间隔排列、四层初始分配与最大接收容量，并保留蝴蝶插入后可能超过初始上限的数量。Up、Middle、Bottom露出的花均可点击，重叠优先前层；Down隐藏。点击移除后按层优先补位，普通补层遵守原容量；XY位置、邻花位移和聚散动画仍使用可重复的本地近似。花种变体按原 `flowerPrefabPath` 解析，保留原表对同一图片的复用。
- **蝴蝶**：第二关原 B 表有 8 只蝴蝶（4绿、4粉），按原百分比条目逐只插入。单只进入普通暂存格；同色两只共用一格并触发当前订单组补单，然后释放该格。特殊对象不加入99朵普通花的进度分母，单只蝴蝶占格也参与满格判断。
- **难度隐藏**：已按原 `diffRange` 隐藏指定花，当前订单组激活后按原检查条件与延迟释放到Bottom；合成可提前释放其对应隐藏花。第二关初始为94朵普通花加8只蝶，另5朵隐藏，普通进度总数仍为99。释放时增添节点，不重建整池。
- **点击区域**：已接入原438个多边形、4个圆形碰撞轮廓，统一按前后顺序命中；图片透明边角不会以矩形按钮挡住后面露出的灰花。蝴蝶的泡泡点击圈保持固定，不随翅膀拍动缩窄。
- **界面流程**：原图首页、设置、暂停、继续、重开、胜利、失败、下一关和返回主页。首关胜利展示已观察的六束预告和单个“下一关”；没有已核实预告的后续关卡仅显示真实本局奖励。时间耗尽后可支付本地 **100金币增加120秒**，保留订单、花池和暂存状态；关闭后进入失败面板。
- **道具**：合成补当前订单的一组剩余花，不一次填满混合花束的全部组；打乱先提升首个当前订单组的缺花，再聚拢散开；清除把普通暂存花移到待回填区，保留蝴蝶，不删除关卡总花数。道具次数使用本地存储，原平台补充次数和视频解锁未接入。
- **入场与水波**：花池按原节奏每批 3～4 朵、间隔 0.05 秒出现，可见花以 0.35 秒 OutCubic 从零缩放进入。水波使用原 55 张 Sprite、6 个动画片段及 442 个 prefab 挂点，播放原换帧、颜色和缩放轨道；初始常驻水波、补层短波和点击后停止分别处理。入场期间倒计时继续推进。
- **按钮与订单动态**：按钮按原 0.1 秒 InOutQuad 缩放，普通按钮按下为 0.9 倍、首页开始按钮为 0.94 倍；首页图标和宝箱读取原动画曲线。收花使用原 0.58 秒飞行参数；订单包含逐朵弹动、切组、完整花篮 0.6 秒离场、按原容器宽度从左侧补位，以及 7 套原 Spine 落花/完成/提示特效。`New` 按“本关解锁、该次开局首次出现的花篮”判断，并非每次补单都显示。

此前已恢复原版访问并观察首关通关、暂停及第二关部分游玩；本轮动态优化时原版 WeApp 读窗失败，未重新进行现场逐帧对照。本轮依据原包静态代码、资源和此前观察实现，并在 Cocos 浏览器预览验证。文档不将静态解析或类型检查当作完整视觉验证。
