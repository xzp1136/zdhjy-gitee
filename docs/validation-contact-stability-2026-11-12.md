# 花池持续抖动修复

用户反馈第二关受挤的花会持续抖动，并明确要求处理整个花池的算法/碰撞稳定性，不只修某一种花。本轮修改 `FlowerPhysics.ts` 的通用稳定策略，不改花朵尺寸、花池密度、原碰撞轮廓数据或分层过滤。

## 复现与原因

使用 Creator 3.8.7 自带真实 Box2D 求解器，把三个原 `cdtx_xrk_01` 胶囊体置于狭窄边界内。旧代码中，三个物体的线速度/角速度可以已接近零，但位置求解器仍在相互冲突的接触约束之间修正姿态。单次旧代码复现最后三秒累计来回转角约 42.72°，三个物体始终保持唤醒。

持续水流和随机转动力会干扰安定，但仅去掉向障碍物内的水流并不足以解决上述位置求解抖动。最终修复没有改变原水流方向、冲量强度或速度上限，而是让稳定受挤的接触组能够真正休眠。

## 通用策略

- 所有花的刚体启用接触监听，以碰撞体所属的节点识别邻接物体，不把同一复合形状的多个 fixture 当成多个邻花。
- 接触持续稳定、速度足够低，且位置/角度变化维持在小范围内约 .8 秒时，进入原生刚体休眠。保留碰撞体，不只冻结渲染图片。
- 受接触约束时不再附加随机旋转冲量。未受阻的花仍按原水流参数漂动。
- 邻花被收走/禁用、邻接关系改变、刚体出现明显速度、发生层切换/缩放/动画恢复时，清除稳定状态并允许继续运动。
- 对多边形拼接接触的短暂闪断设置 .12 秒容差，避免接触边缘反复出现/消失导致持续唤醒；被删除或禁用的邻花不等待此容差。

稳定判断的速度、位移、角度阈值及等待时间均为本次 Cocos 体验优化参数，不作为“从 Unity 原包提取的数值”记录。没有改变池壁、花朵数量/尺寸或添加吸引补洞力。

- 现有自由漂动、固定步、分层碰撞、池壁、质量、入场、上浮、打乱、点击和释放回归继续通过。
