# 原版结算、失败与暂停面板提取笔记

依据用户提供的 Unity 运行包、`level2-layout.json`、资源清单，以及本次对 `resources.assets` 中原始预制体的只读解析。本代理没有操作原版 UI，没有修改 Cocos 脚本或场景；另纳入 root 代理随后实际通关首关的运行时观察。

最关键的修正：`original/ui/over/tittle` 的实际图文是 **“下关解锁花束”**，原节点叫 `imgUnlockTitle`，对应上半屏的 `UnlockFlowerParent` 花束预告区域。它不是通用“通关成功”标题。原版胜利面板默认结构确实使用这张图，但不能把它放在没有花束预告的任意结算弹窗上。

## 新增：原版首关实际通关观察（优先于静态默认值）

root 已实际完成原版首关，确认胜利画面就是“下关解锁花束”，并展示3列×2行的6张卡，依次为 **暮云笺、浅梦来信、小竹兰、浅绯、翠扶摇、浅棕笺**；奖励为 **金币+10、星星+3**；底部仅一个绿色“下一关”按钮，**没有主页按钮**。因此首关应实现这个分支；下文静态预制体中的双按钮和`+0`不能覆盖上述运行时证据。花束图片的确切资源组合另行核对，不能仅由名字猜图。

## 证据范围与坐标约定

- 原结算预制体：`prefabs/ui/over`，`resources.assets` GameObject **4914**，控制组件 `OverUIControl` **22170**。玩法场景实例位于 `/Canvas/Over`，组件 **842**，其主要美术、文字、坐标与预制体一致。
- 原暂停预制体：`prefabs/ui/pauseview`，GameObject **6234**，组件 `PauseViewControl` **21960**。
- 下表原始数值使用 **1080×1920** UI 单位、中心为原点、Y 向上；尺寸是 RectTransform 的尺寸，不是 PNG 文件像素尺寸。
- 迁移到当前 750×1334 画布时，原始坐标、尺寸、字号按 **750/1080 = 25/36** 缩放。表内“750 参考”已换算。未特别注明时，pivot 为 `(0.5,0.5)`。
- “默认显示/隐藏”来自序列化 `active` 状态，不能证明每次运行时的分支选择。奖励金额、标题切换条件、解锁花束名单仍由原脚本动态赋值，尚未恢复完整业务。
- 文中的 `original/...` 是 Cocos resources 路径，实际 PNG 均在 `assets/resources/original/`。应加载对应 `/spriteFrame`。

### 通关标题应怎样处理

1. 有已核实的下关花束预告时，整组还原 `imgUnlockTitle + UnlockFlowerParent`，标题可以使用原图。

## 六、实施优先级与尚未证实的内容

1. 首关优先按已观察到的6张花束预告、金币+10、星星+3和单个绿色下一关还原。双按钮仅是原预制体静态默认，勿覆盖首关实测。
2. 失败使用木框+原插画+“闯关失败”图片，保留主页与再来一局；如暂未实现体力消耗，不应显示已经接入扣体力逻辑的假象。
3. 暂停恢复三行开关和横排按钮，保持模态阻止底层点击，并验证继续游戏后计时恢复。
4. 本代理只解析静态资源/层级/数值，首关实测由root补充；其它关卡动态标题分支、奖励公式、失败广告流程、实际体力扣除、动效时序仍未验证。继续对照原版运行后再宣称这些行为一致。


## 七、首关六束预览数据与裁切坐标

组合数据位于 `assets/resources/original/data/win-preview-level1.json`，合成预览位于 `docs/reference/win-preview-level1.jpg`。每束包含按绘制顺序排列的 `layers`，每层具有 `resource/x/y/width/height/angle`。容器与花朵沿用原预制体挂点；随后成功提取了原 VaseInfoConfig：六个名字与容器路径现已按原表校正，标记为 `original-vase-table`；具体花种仍依据 root 的颜色与花型观察，最后一束后层向日葵为推定。详情见 `original-config-extraction.md`。

需要特别注意：UnityPy 的 `Sprite.image` 输出的是 `m_RD.textureRect` 裁切区域，而原 Sprite 的 `m_Rect` 可能更大，二者不能直接混用。组合数据已用 `m_RD.textureRectOffset` 还原裁切图中心：`delta = (offset + cropSize/2 - logicalSize/2) × scale`，并保留原节点旋转。容器前景 mask 也必须使用裁切后的实际尺寸，不能拉伸到容器整幅尺寸。例如篮子 `bkt1_3zy_01` 的逻辑尺寸为267×285，而对应 mask 裁切图仅228×77。原始导出 PNG 未被修改。
