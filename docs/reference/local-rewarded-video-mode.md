# 当前关闭广告的奖励模式

2026-11-07 用户要求“暂不接广告，保留功能与弹窗，点击需视频按钮直接触发功能”。`FlowerRewardedVideo.ts` 的共享实例显式使用 `adsEnabled: false`，不读取 `wx` 或调用任何广告 SDK。广告回调被本地异步完成边界替代，界面的原有视频图标、按钮与弹窗保留。

| 入口 | 点击确认后的行为 | 数量依据 |
| --- | --- | --- |
| 锁住的花束位 | 解锁所点位置，并按规则补订单、吸入匹配暂存花 | 复用 `FlowerRules.unlockOrderSlot()` |
| 时间耗尽面板的视频继续 | 不扣金币、增加120秒，保留订单与花池 | 原 `TimeUpOverControl.ShareSuccess43161` / `AddGameTime43164` 与金币路径共用续时链；常量120 |
| 合成、打乱、清除次数耗尽 | 弹窗领取对应道具1次，刷新次数；不自动使用 | 原 `Config56047` 三条 `PropInfo.num=1`；`ShowView42435` 接收数量，`AddProp42438` 只加库存并刷新UI |

100金币续时和60金币暂存扩格仍走原金币路径。主页现有签到、新手礼包、分享说明、福利说明不是已实现的视频按钮，本次未添加未经证实的奖励数额。

服务按入口锁住尚未完成的领奖请求；界面另有点击、失效节点与场景版本检查。订单已解锁、道具库存已补充、规则已恢复游戏后，同一次请求不能再重复产生奖励。后续再次耗尽道具或再次时间耗尽，可以发起新的合法领取。

未来启用广告时，需明确设置 `adsEnabled: true` 并提供真实 `provider`；服务只接受其返回 `true`，缺少适配器或返回未完成均不发奖。当前没有连接这一模式。

测试覆盖关闭广告时不调用 provider、并发去重、请求失败后可重试、换场取消、免费续时不扣币/不重复恢复、花束解锁事件同步、道具只补1次且不自动使用。
